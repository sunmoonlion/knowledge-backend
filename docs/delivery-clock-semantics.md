# 投递时钟与显式状态

执行租约显式释放后，`expires_at` 写 PostgreSQL `'-infinity'::timestamptz`。
它表示已释放，不是释放发生的审计时间；保留原 owner/epoch 行，使接任者 epoch 递增，
迟到释放不能撤销新租约。不能删除租约行重置 epoch，也不能用当前时间表达永久失效：
墙钟回拨会让后者重新满足有效租约谓词，阻塞重试甚至使旧 owner 再次续租。
取得/续期仍要求精确所有者及 epoch；有效 TTL 仍由数据库时钟判定。

`available_at` 是下一次发布的等待门槛，不是审计时间。无预约新消息、显式死信重放和
对账重新入队写负无穷，表示没有额外等待。实际失败退避仍写未来时间；真正预约由
不可变 `sunmoonai.not_before.v1` 约束，重放/对账不得绕过它。`created_at`、`updated_at`、
`published_at`、死信/重放审计时间继续记录真实时间。已有记录不做批量改写。

只读观测与执行的预约语义一致：没有 not-before 就不是预约消息，不能把 `created_at`
当隐含预约门槛；消息年龄仍从创建/预约时间计算，并把回拨导致的负年龄截为零。
指标快照不等于工作进展或监控系统已接线。

这一修复不使墙钟成为单调时钟，不承诺活动租约 TTL、deadline、真实退避、预约、
发布超时对账在任意校时下不变。运行环境仍需可靠且单一的校时路径和时间异常监控。
旧版本 SQL 能比较负无穷，原有列类型无需迁移；运维工具不得把等待门槛误当常规日期，
也不得凭负无穷认为消息已完成或可以删除。幂等/引用与保留窗不在本次修改范围。

回归使用一次性真实 PostgreSQL，仅在测试引擎 SQL 层注入时钟偏移，不修改宿主时间或
数据库全局函数。覆盖释放后再领取、旧 owner 续租/写入拒绝、接任者保护、立即投递、
重放/对账、显式预约与真实退避；领域测试另复用原取消/未知回执/轮询断言。
